# Data Model: Gestão de Doações Comunitárias

## Conventions

- Primary keys are UUIDs generated by the application.
- All instants use `timestamptz` in UTC; calendar dates use `date`.
- Money uses `numeric(14,2)` plus ISO 4217 `currency`, default `BRL`.
- Inventory quantities use `numeric(14,3)` and must be positive when moved.
- E-mail is trimmed and lowercased; CPF/CNPJ and phone are stored normalized to digits.
- Mutable records carry `created_at`, `updated_at` and integer `version` for optimistic checks.
- Historical business records are deactivated or superseded, never hard-deleted through normal
  product flows.
- Secrets are never stored directly. Session and access-link tokens are represented by SHA-256
  hashes; passwords are represented by Argon2id hashes.

## Identity and Access

### users

| Field | Type | Rules |
|---|---|---|
| id | uuid | Primary key |
| name | varchar(160) | Required |
| email | varchar(254) | Required, normalized, unique |
| role | enum | `GENERAL_ADMIN`, `FINANCE`, `INVENTORY_VOLUNTEER` |
| status | enum | `PENDING`, `ACTIVE`, `INACTIVE`, `BLOCKED` |
| password_hash | text nullable | Required before first activation; Argon2id only |
| failed_login_count | smallint | Default 0, range 0..5 |
| last_login_at | timestamptz nullable | Updated only on success |
| blocked_at | timestamptz nullable | Required only when status is `BLOCKED` |
| created_by | uuid nullable | Self-reference; null only for bootstrap administrator |
| created_at / updated_at | timestamptz | Required |

State transitions:

```text
PENDING ──set first password──> ACTIVE
ACTIVE ──5 consecutive failures──> BLOCKED
BLOCKED ──general admin unlock──> ACTIVE
ACTIVE/BLOCKED/PENDING ──deactivate──> INACTIVE
INACTIVE ──reactivate──> ACTIVE or PENDING, based on password presence
```

- Successful login before the fifth failure resets `failed_login_count` to zero.
- A blocked account remains blocked after password changes and can only be unlocked by a general
  administrator.
- Deactivation revokes all active sessions in the same transaction.

### sessions

| Field | Type | Rules |
|---|---|---|
| id | uuid | Primary key |
| user_id | uuid | Required FK to users |
| token_hash | char(64) | Required, unique |
| created_at | timestamptz | Required |
| expires_at | timestamptz | Required, 8 hours after creation |
| revoked_at | timestamptz nullable | Null while active |
| last_seen_at | timestamptz | Operational metadata |
| ip / user_agent | text nullable | Minimized audit context |

An accepted session requires an unexpired, unrevoked row and an `ACTIVE` user. Role changes and
deactivation therefore take effect on the next request.

### login_attempts

| Field | Type | Rules |
|---|---|---|
| id | uuid | Primary key |
| user_id | uuid nullable | FK when the normalized e-mail matches |
| attempted_email | varchar(254) | Required, normalized |
| occurred_at | timestamptz | Required |
| ip | inet nullable | Access restricted to general administrator |
| user_agent | text nullable | Truncated to a safe maximum |
| result | enum | `SUCCESS`, `INVALID_CREDENTIALS`, `PENDING`, `INACTIVE`, `BLOCKED` |

Retention is 180 days by default. Logs must not repeat the attempted password or session token.

### access_links

| Field | Type | Rules |
|---|---|---|
| id | uuid | Primary key |
| purpose | enum | `INVITE`, `PASSWORD_RESET`, `DONOR_ACCOUNT` |
| token_hash | char(64) | Required, unique |
| user_id | uuid nullable | Required for invite/reset |
| donor_id | uuid nullable | Required for donor account |
| created_at | timestamptz | Required |
| expires_at | timestamptz | Exactly 30 days after creation |
| revoked_at | timestamptz nullable | Null while active |

Exactly one of `user_id` or `donor_id` is set, consistent with `purpose`. Links are reusable until
expiration or revocation. Reissuing a link creates a new row; it does not silently extend an old
one.

### audit_events

| Field | Type | Rules |
|---|---|---|
| id | uuid | Primary key |
| actor_user_id | uuid nullable | Null for public/system action |
| actor_kind | enum | `USER`, `DONOR_LINK`, `PUBLIC`, `SYSTEM` |

| occurred_at | timestamptz | Required |

Audit rows are append-only for application roles.

## Donors and Recurrence

### donors

| Field | Type | Rules |
|---|---|---|
| id | uuid | Primary key |
| name | varchar(160) | Required for identified donors |
| email | varchar(254) nullable | Normalized |
| phone | varchar(20) nullable | Digits only |
| document | varchar(14) nullable | Valid normalized CPF/CNPJ; partial unique index |
| relationship_type | enum | `ONE_OFF`, `RECURRING`, `IN_KIND` |
| origin | enum | `PUBLIC`, `IN_PERSON`, `ADMIN` |
| review_status | enum | `CLEAR`, `PENDING_REVIEW` |
| created_at / updated_at | timestamptz | Required |

Matching occurs in one transaction:

1. exact document when provided;
2. otherwise exact normalized e-mail;
3. otherwise exact normalized phone;
4. name is never a matching key.

If e-mail and phone point to different donors, create a new `PENDING_REVIEW` donor from the
submitted identity and a review case. The contribution links to that provisional donor, never to a
conflicting existing donor.

### donor_match_reviews

| Field | Type | Rules |
|---|---|---|
| id | uuid | Primary key |
| submitted_donor_id | uuid | Required FK to provisional donor |
| candidate_donor_ids | uuid[] | At least two distinct candidates or one conflicting candidate |
| reason | enum | `IDENTIFIER_CONFLICT`, `POSSIBLE_DUPLICATE` |
| status | enum | `OPEN`, `KEEP_SEPARATE`, `MERGED` |
| opened_at | timestamptz | Required |
| resolved_at / resolved_by | nullable | Both set together on resolution |
| resolution_note | text nullable | Required when resolved |

Finance and general-admin roles may resolve reviews. A merge runs transactionally, moves references
to the surviving donor, preserves an audit event and marks the provisional record as merged rather
than deleting its history.

### recurring_subscriptions

| Field | Type | Rules |
|---|---|---|
| id | uuid | Primary key |
| donor_id | uuid | Required FK |
| amount | numeric(14,2) | Greater than zero |
| currency | char(3) | `BRL` in MVP |
| status | enum | `ACTIVE`, `PAUSED`, `CANCELLED` |
| method | enum | `PIX`, `CARD` |
| next_charge_date | date nullable | Required while active; simulated reference only |
| destination_type | enum | `PROJECT`, `MOST_NEEDED` |
| project_id | uuid nullable | Required iff destination is `PROJECT` |
| created_at / updated_at | timestamptz | Required |

State transitions:

```text
ACTIVE ──pause──> PAUSED ──resume──> ACTIVE
ACTIVE/PAUSED ──cancel──> CANCELLED
CANCELLED ──x──> any state
```

Only future simulated charges use a changed amount. Historical ledger entries never change.

| Field | Type | Rules |
|---|---|---|

| idempotency_key | uuid | Required, unique |

| destination_type / project_id | enum / uuid nullable | Conditional project relationship |
| submitted_identity | jsonb nullable | Minimized input until donor match completes |

Confirmation is idempotent: a repeated request returns the existing result. `CONFIRMED` creates

## Transaction Boundaries

### Public donation confirmation

1. Lock simulation by id and verify idempotency key.
2. If already confirmed, return the existing result.
3. Match or create donor; open review on conflicts.
4. Insert ledger entry and optional recurring subscription.
5. Mark simulation confirmed and link created records.
6. Insert audit event.
7. Commit once; any failure rolls back all steps.

### Inventory distribution or discard

1. Validate project or reason according to movement type.
2. Select and lock eligible lots in expiry order.
3. Validate requested quantity against locked total.
4. Insert movement and lines.
5. Decrement each lot and derive its state.
6. Insert audit event and commit.

### Login and blocking

1. Normalize e-mail and load user in a transaction.
2. Record denied status immediately for pending, inactive or blocked account.
3. Verify Argon2id hash outside the transaction, then lock/reload the user for update.
4. On failure, increment consecutive count; the fifth sets `BLOCKED` and `blocked_at`.
5. On success, reset count, set last login and create hashed session.
6. Record the attempt without exposing which e-mails exist to untrusted observers.

## Required Indexes and Constraints

- Unique case-insensitive user e-mail.
- Partial unique donor document where document is not null.
- Non-unique normalized donor e-mail and phone indexes for matching.
- Unique session token hash, access-link token hash and payment idempotency key.
- Ledger indexes on `(occurred_on, type)`, `project_id`, `donor_id`, `status` and `origin`.
- Inventory lot index on `(item_id, status, expires_on, received_on)`.
- Movement indexes on date, project and type.
- Publication index on `(published_at DESC, id DESC)`.
- Check constraints for positive money/quantity, conditional project relationships, link owner and
  document types.

## Retention and Deletion

- A scheduled daily maintenance command deletes expired sessions after 30 days and old login
  attempts after 180 days.
- Expired/revoked access-link rows remain 180 days for audit, containing only token hash.
- Audit, finance and document metadata default to five-year retention.
- Donor identity may be anonymized after the approved retention period while financial totals and
  immutable audit references remain.
- Generated files follow the retention of their metadata and are removed only after a successful
  off-site backup and an audited retention job.

The default periods are operational policy, not a legal conclusion; production activation requires
documented approval by the capela's data controller.
